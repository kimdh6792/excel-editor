## 파일 구조

```
src/
  App.tsx              툴바, 열기/저장, 최근 파일, 더티 추적, 경고 배너
  univer-worker.ts     수식 엔진 워커 (메인 스레드 차단 방지)
  fs/file.ts           Tauri dialog+fs+IPC, 브라우저 폴백
  xlsx/
    normalize.ts       ExcelJS가 못 읽는 파일 복구
    import.ts          xlsx → Univer 스냅샷
    export.ts          Univer 스냅샷 → xlsx
    style.ts           ExcelJS Style ⇄ Univer IStyleData (양방향, 한 파일)
    color.ts           argb / 테마+tint / 인덱스 팔레트 → #rrggbb
    units.ts           문자폭↔px, pt↔px, Date↔시리얼
    range.ts           A1 참조 ⇄ Univer IRange
    filter.ts          autoFilter ⇄ Univer 필터 리소스
    inspect.ts         손실될 기능 탐지
    snapshot.ts        빈 통합 문서 (파서 의존 없음)
  csv/
    encoding.ts        BOM / UTF-8 / CP949 감지, UTF-8+BOM 쓰기
    delimited.ts       RFC 4180 파서·직렬화, 구분자 감지
    convert.ts         구분자 텍스트 ⇄ Univer 스냅샷, 타입 추론
  print/
    options.ts         인쇄 설정 타입·기본값 (툴바가 렌더러 없이 읽는다)
    collect.ts         라이브 워크북 → 인쇄 범위 선정 (시트/선택/전체)
    area.ts            스냅샷 영역 → 셀 격자 평탄화 (서식·너비·병합·숨김)
    html.ts            셀 격자 → HTML 표 (인라인 서식, 이스케이프)

src-tauri/src/
  lib.rs               플러그인 등록, Finder 열기·드래그앤드롭 → scope 부여 후 프런트에 전달
  pending.rs           UI 준비 전 도착한 열기 요청 큐
  recent.rs            최근 파일 목록 + fs scope 재부여 + 백업 복사
  print.rs             웹뷰 인쇄 (NSPrintOperation) 커맨드
```

`style.ts` 가 양방향 변환을 한 파일에 담고 있는 건 의도적이다. 한쪽에 필드를 추가하면
반대쪽도 반드시 짝을 맞춰야 하는데, 파일을 나누면 그 짝이 어긋나면서 왕복 버그가 생긴다.

## 부딪힌 라이브러리 함정들

실제 파일과 라이브러리 동작을 확인하며 우회한 지점들. 전부 테스트로 고정해 뒀다.

### `r` 속성 없는 xlsx를 ExcelJS가 못 읽는다

SpreadsheetML에서 `<row>`·`<c>` 의 `r`(위치) 속성은 선택이고, 없으면 문서 순서로 위치가
결정된다. Excel과 Numbers는 이를 처리하지만 ExcelJS는 `Invalid row number in model` 로
파일 전체를 거부한다. DataGrip 등 여러 내보내기 도구가 이 최소 형식을 쓴다 — 즉 **열어야 할
이유가 큰 파일이 하필 안 열린다.**

`normalize.ts` 가 파싱 직전에 위치를 명시적으로 채워 넣는다. 정규화 결과는 파서에만
전달되고 사용자 파일에는 쓰이지 않는다.

### 스타일 dedup 키가 서로 다른 서식을 합쳐 버렸다

`JSON.stringify(style, Object.keys(style).sort())` 의 두 번째 인자 배열은 정렬 힌트가 아니라
**중첩 객체까지 재귀 적용되는 속성 허용목록**이다. 그래서 `{n:{pattern:'yyyy-mm-dd'}}` 와
`{n:{pattern:'#,##0.00'}}` 가 둘 다 `{"n":{}}` 로 직렬화돼 날짜 셀이 통화 서식을 물려받았다.

키를 재귀적으로 정렬하는 직렬화 함수로 교체했다 (`style.ts`의 `stableKey`).

### 병합된 셀의 값이 복제됐다

ExcelJS는 병합 영역의 종속 셀에서 `cell.value` 를 읽으면 **master의 값을 돌려준다.**
그대로 가져오면 Univer 쪽에 같은 값이 영역 전체에 박히고, 병합을 풀면 드러난다.
종속 셀은 서식만 가져온다.

### 셀도 높이도 없는 숨긴 행이 저장에서 사라졌다

ExcelJS `Row.model` 은 `height || cells.length` 가 거짓이면 `null` 을 반환해 행을 아예
직렬화하지 않는다. 숨김 플래그만 있는 행은 통째로 유실된다. 그런 행에는 기본 행 높이를
지정해 실체를 만들어 준다(보이는 결과는 동일).

### 행 높이·열 너비가 저장할 때마다 조금씩 밀렸다

xlsx는 pt와 문자폭, Univer는 px를 쓰고 변환이 정확히 가역적이지 않다. 원본 값을 `custom`에
실어 보내고, px가 그대로면 원본 값을 다시 써서 **건드리지 않은 행/열은 반복 저장에도 고정**된다.
리치 텍스트와 하이퍼링크도 같은 방식으로, 텍스트가 변하지 않았다면 원본을 복원한다.

### ExcelJS는 `fullCalcOnLoad` 를 쓰기만 하고 읽지 않는다

검증을 리로드한 객체가 아니라 `xl/workbook.xml` XML 자체에 대해 해야 한다.

### CP949를 UTF-8보다 먼저 시도하면 안 된다

CP949 디코더는 어떤 바이트열이든 받아들여 **절대 실패하지 않는다.** 먼저 시도하면 진짜
UTF-8 파일이 조용히 깨진다. 엄격(`fatal: true`) UTF-8을 먼저 시도하고 **실패할 때만**
CP949로 간다.

### 1900-03-01 이전 날짜는 하루 어긋난다

Excel의 1900 체계에는 존재하지 않는 1900-02-29가 들어 있다. 선형 일수 계산은 Excel보다 1 크다.
ExcelJS도 같은 선형 변환을 쓰므로 앱 내부는 일관되고, 실제로 문제되는 경우는 없다.
테스트(`units.test.ts`)에 명시해 뒀다.

### Finder 더블클릭 요청이 UI보다 먼저 도착한다

앱이 꺼진 상태에서 파일을 더블클릭하면 macOS가 앱을 띄우면서 `RunEvent::Opened` 를
**시작 도중에** 보낸다. 웹뷰가 로드되기 전이라 받을 리스너가 없어 요청이 사라지고,
사용자는 빈 표를 보게 된다. 앱이 이미 떠 있을 때는 정상 동작해서 놓치기 쉽다.

`pending.rs` 가 프런트엔드가 준비됐다고 알릴 때까지 경로를 큐에 보관한다. 프런트엔드는
Univer 초기화와 리스너 등록을 마친 뒤에야 `frontend_ready` 를 호출하고, 그 응답으로
밀린 경로를 받는다.

### 수식 재계산이 "편집됨"으로 잡힌다

Univer의 수식 엔진은 계산 결과를 일반 `set-range-values` 뮤테이션으로 기록해서, 명령 ID만
봐서는 사용자 편집과 구분되지 않는다. 수식이 있는 파일을 열면 손대지도 않았는데 저장 안 됨
표시가 켜진다. 엔진이 계산 구간을 start/stop으로 감싸므로, 그 사이에 오는 뮤테이션은
더티 추적에서 무시한다 (`App.tsx`의 `CALC_LIFECYCLE`).

### WKWebView에서 `window.print()` 는 아무 일도 하지 않는다

JS의 `window.print()` 는 WKWebView에서 **예외도 없이 조용히 무시된다.** 웹 쪽만 보고
구현하면 동작하는 것처럼 보이면서 아무것도 인쇄되지 않는다.

Rust를 거쳐야 한다. `WebviewWindow::print()` → wry가 웹뷰로 `NSPrintOperation` 을 만들어
창에 시트로 띄운다 (`print.rs`). 그 덕에 용지·방향·부수·"PDF로 저장" 은 macOS 기본
인쇄 대화상자가 전부 처리한다.

주의할 점이 두 가지다.

- **커맨드는 대화상자가 떠 있는 상태로 반환된다.** `runOperationModalForWindow` 는 시트
  모달이라 비동기다. 그래서 인쇄용 DOM을 호출 직후에 치우면 빈 페이지가 나온다. 지금은
  다음 인쇄나 다른 문서를 열 때까지 그대로 남겨 둔다 (`App.tsx` 의 `loadSnapshot` 이 비운다).
- **wry의 `PrintOptions` 는 여백만 넘긴다.** 용지 방향을 앱에서 미리 지정할 수 없어
  `@page { size: landscape }` 도 통하지 않는다. 가로 인쇄는 사용자가 대화상자에서 고른다.

### 캔버스는 인쇄할 수 없다

Univer 그리드는 캔버스다. 그대로 인쇄하면 **화면에 보이는 픽셀 한 페이지**가 나오고 나머지는
잘린다. 그래서 인쇄는 스냅샷에서 HTML 표를 새로 그린다 (`src/print/`). `@media print` 가
툴바·경고·그리드를 숨기고 그 표만 남긴다.

표시 문자열은 직접 만들지 않고 `FRange.getDisplayValues()` 를 쓴다. 숫자 서식 적용은 이미
Univer가 하는 일이고, 다시 구현하면 화면과 인쇄물이 서로 다르게 보이는 두 번째 포매터가 생긴다.

"한 페이지 폭에 맞춤" 은 배율이 아니다. 표를 `width:100%` 로 두고 각 열에 전체 폭에 대한
**비율**을 주면, 열 사이 비례는 유지되고 절대 크기는 프린터가 정한다. 가로 페이지 분할이
없으므로 실제 크기로 인쇄할 때 용지보다 넓은 시트는 잘린다.

### 파일에서 온 색·글꼴 이름이 속성 안에 들어간다

셀 서식은 인라인 `style` 속성으로 나간다. 즉 `cl.rgb` 나 `ff` 값이 따옴표를 닫고 나올 수
있으면 임의 속성을 주입할 수 있다. `html.ts` 의 `safeColor` 는 리터럴 hex만 통과시키고,
`safeFontFamily` 는 따옴표·세미콜론·콜론·괄호를 전부 제거한다. 테스트로 고정해 뒀다.

## 파일 접근 권한 설계

`fs` 권한에 **정적 경로 스코프를 두지 않았다**(`src-tauri/capabilities/default.json`).
`tauri-plugin-dialog` 이 사용자가 다이얼로그에서 고른 경로에 대해 런타임 fs 스코프에
`allow_file` 을 호출하고, `tauri-plugin-fs` 의 `resolve_path` 가
`fs_scope.scope.is_allowed(...) || scope.is_allowed(...)` 로 런타임 스코프를 함께 검사한다.
따라서 **사용자가 직접 고른 파일만** 읽고 쓸 수 있고, 파일시스템 전체를 여는 `**` 글롭이 필요 없다.

파일이 들어오는 경로가 넷으로 늘어나면서 이 불변식을 유지하는 게 설계의 핵심이 됐다.

| 경로 | scope를 누가 주나 |
|---|---|
| 다이얼로그 | 플러그인이 자동으로 |
| Finder 더블클릭 | `lib.rs` 가 `RunEvent::Opened` 를 받아 **Rust에서** |
| 드래그앤드롭 | `lib.rs` 가 `WindowEvent::DragDrop` 을 받아 **Rust에서** |
| 최근 파일 | `grant_recent` 가 재부여 — 단 **Rust가 기록한 경로만** |

마지막 줄이 중요하다. scope 부여는 재시작하면 사라지므로 어제 연 파일을 다시 열려면
재부여가 필요한데, 프런트엔드가 임의 경로를 넣고 허용받을 수 있으면 안 된다. 그래서
최근 목록을 Rust가 소유하고, 목록에 넣는 `record_recent` 가 넣기 전에 `is_allowed` 로
검증한다. 프런트엔드가 지어낸 경로는 스코프에 없으므로 기록 자체가 거부된다.

백업 복사도 Rust에 있다. `이름.bak.xlsx` 는 사용자가 고른 적 없는 경로라서, 프런트엔드가
쓰려 하면 스코프가 — 옳게 — 거부한다.

## CSV 처리 세부

**인코딩 감지** (`csv/encoding.ts`) — BOM(UTF-8/UTF-16LE/BE)을 먼저 보고, 없으면 엄격 UTF-8,
실패하면 CP949. 저장은 항상 UTF-8 + BOM. BOM이 없으면 Excel이 시스템 코드페이지로 읽어
한글이 깨진다.

**구분자 감지** (`csv/delimited.ts`) — `,` `\t` `;` `|` 각각으로 앞 20줄을 파싱해, 모든 행이
같은 필드 수로 쪼개지는 정도를 점수화한다. 일관성이 지배적이고 필드 수는 동점일 때만
가른다. 값 안에 콤마가 든 탭 구분 파일도 올바르게 판정한다.

**타입 추론** (`csv/convert.ts`) — 숫자로 바꾸는 조건:

1. `-?(0|[1-9]\d*)(\.\d+)?([eE][+-]?\d+)?` 에 정확히 맞을 것 (앞자리 0 거부)
2. 유효숫자 15자리 이하 (float64가 정확히 표현 가능한 범위)

날짜와 `TRUE`/`FALSE` 는 **추론하지 않는다.** 날짜 서식이 걸린 숫자를 CSV로 쓸 때만
시리얼 대신 `2026-03-15` 형태로 내보낸다.

**실측** — 2.4MB·34,318행·7열 CSV: 파싱 95ms, 쓰기 40ms, 201,708셀 전부 왕복 일치.

## 다른 OS로 포팅하려면

기반 기술(Tauri, Univer, ExcelJS)은 전부 크로스 플랫폼이고 CP949 디코딩도 표준 웹
인코딩이라 원리상 돌아갈 구조다. 다만 **빌드조차 시도해 본 적이 없다.**

인쇄도 손봐야 한다. `print.rs` 가 쓰는 `WebviewWindow::print()` 는 Tauri 문서상 **wry에서
macOS만 지원**이다. 다른 OS에서는 프런트엔드의 `printWindow()` 가 브라우저 분기처럼
`window.print()` 를 직접 부르면 된다 — WKWebView와 달리 WebView2와 WebKitGTK는 JS 호출이
동작한다. `src/print/` 의 HTML·CSS는 그대로 쓴다.

확실히 아는 공백은 하나다. **파일 더블클릭 경로가 macOS 전용**이다 — macOS는 OS가
`RunEvent::Opened` 로 경로를 넘기고 `lib.rs` 가 그것만 처리한다. Windows·Linux는 경로를
커맨드라인 인자로 넘기는데 그 처리가 없다. 그 환경에서 빌드하면 앱은 뜨지만 더블클릭한
파일이 열리지 않는다. 열기 버튼과 드래그앤드롭은 동작할 것이다.

시작점: 앱 기동 시 `std::env::args()` 를 읽어 `announce_paths` 로 흘려보내면 된다.
앱이 이미 떠 있을 때 두 번째 파일을 여는 건 single-instance 플러그인이 추가로 필요하다.

## 성능 메모

수식 엔진 워커가 Univer 코어를 별도 청크(~7MB)로 한 번 더 번들한다. 메인 스레드 차단을
막는 대가다. 로컬 앱이라 디스크에서 읽으므로 체감 비용은 작다.

파서(ExcelJS, 약 1MB)는 동적 import로 분리돼 있어 시작 시에는 로드되지 않는다.
파일을 처음 열거나 저장할 때 읽힌다.

릴리스 빌드: `.app` 약 8.3MB, `.dmg` 약 5.9MB.
